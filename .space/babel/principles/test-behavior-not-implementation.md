# 内部実装より観測できる振る舞いをテストする

## 適用条件

テストを追加・変更するとき、既存テストを残すか判断するとき。

## 判断の指針

テスト対象を具体的な入力で実行し、利用者が観測できる出力や副作用を、対象の実装から独立した期待値と比較する。

- 対象が何もしなくても成功するテストになっていないか確認する。アサーションなし、曖昧な真偽判定、呼び出された事実だけの確認を避ける。
- 出力がないケースは、対になる入力で出力が存在するケースも確かめ、処理が働いていることを示す。
- 期待値を検証対象と同じ関数で計算しない。固定した具体的な期待結果を使う。
- 定数・プロンプト・設定値をそのまま書き写して固定するより、それを使う処理の結果を確認する。
- モックは呼び出し回数だけでなく、渡された内容や観測可能な状態変化を確認する。
- 用意したfixtureを読み返すだけで、対象が実行されないテストを残さない。

表のキーの整合や親の存在など、関係の不変条件を検証するテストと、コンパイル時の型検証には意味がある。アサーション名だけで機械的に削除せず、どの不具合を検出できるかで判断する。
