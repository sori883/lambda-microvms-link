# コードの履歴調査（gitとリポジトリ内の資料）

## この情報源に含まれるもの

- コミット履歴。メッセージ、日時、作者、差分。
- `gh` で取得するPRの説明、レビューコメント、議論。
- コード内のコメント、TODO、FIXME、非推奨化の注記。
- リポジトリで管理しているADR（アーキテクチャ決定記録）。
- テスト。名前やアサーションが、変更の動機となった境界条件を表す場合がある。
- 同じコミットで変更された関連ファイル。同時変更の手がかり。
- CHANGELOG、リポジトリ内のリリースノート。
- コミットメッセージやPR本文に書かれた課題・チケットID。

コードに直接結び付く記録を調べる。履歴の欠落やPRの取得可否によって調査できる範囲は変わるため、根拠の所在と取得できた範囲を記録する。

## 調べ方

起点となるコミット一覧を広げる。

```bash
# 改名を追跡したファイルの全履歴
git log --follow --oneline -- <file>

# 指定した文字列を追加または削除したコミット
git log -S '<exact_string_from_code>' -- <file>

# 正規表現で探す場合
git log -G '<regex>' -- <file>

# 各行を誰がいつ書いたか
git blame -L <start>,<end> <file>

# 特定コミットの差分全体
git show <hash>

# 二つの時点の間でファイルに影響したコミット
git log <old>..<new> -p -- <file>
```

実質的な変更を含むコミットごとに、PRを特定でき、`gh` が利用できる場合はPRの背景を取得する。

```bash
# マージコミットやブランチからPR番号を探す
git log -1 --format=%B <hash>

# 本文、レビュー、関連課題を含むPRの情報
gh pr view <number> --json title,body,author,createdAt,mergedAt,labels,closingIssuesReferences,comments,reviews,files

# reviewsとcommentsに重要な手がかりがある
```

コード以外の資料も探す。

```bash
# ADRはdocs/adr/などに置かれることが多い
rg -l -i 'architecture.decision' --glob '*.md'

# 対象付近のTODOやFIXME
rg -n -C2 '(TODO|FIXME|HACK|XXX|NOTE)' <target_file>

# 関連テスト。名前に理由が表れる場合がある
rg -l '<symbol>' --glob '*test*'
```

Git履歴やPRが利用できない場合は、取得できなかった範囲と理由を記録し、読めるコードコメント・テスト・設計資料を調べる。資料が参照する外部のチケットや障害のIDは手がかりとして残し、原資料を確認した根拠とは扱わない。

## 有用な根拠の例

- 変更内容だけでなく、解決する問題を説明するPR本文。
- 代替案を議論した長いレビューのやり取り。
- 対象行の近くにある、自明でない制約を説明するコメント。
- コードの動機となった境界条件が分かる `test_handles_edge_case_when_X` のようなテスト名。
- チケットや障害のIDを参照するコミットメッセージ。
- ユーザーから見た理由を説明するCHANGELOGの記載。

## 注意点

- **squashによる履歴の欠落。** PRをsquashしている場合、ブランチ内の個別コミットは失われる。PR本文とコメントを確認する。
- **誤解を招くコミットメッセージ。** 「小さなリファクタリング」に意図的な動作変更が含まれる場合がある。メッセージだけでなく差分を見る。
- **理由を理解せずコピーされたパターン。** 同じパターンがコードベースのどこで始まったかを探し、そのコミットを調べる。
- **ボットのコミットや自動マージ。** Dependabot、Renovate、自動バックポートには通常、採用理由がない。意図を探す際は飛ばす。
- **コードを意図の証拠にすること。** 理由の根拠はコミットメッセージ、PR、コメント、テスト、文書に求める。「関数名がXだから」を意図の証拠にしない。

## 返す情報

質問に関係するコミット・PR・コメントごとに、次を返す。

- 正確な文言の引用。
- ハッシュ、PR番号、ファイルと行番号。
- 作者と日付。
- 質問に明示的に答える直接の根拠か、状況証拠か。
