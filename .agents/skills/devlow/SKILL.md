# 開発作業を進める

最初に [全体フロー](references/workflow.md) を読み、依頼の終了地点、必要な工程、成果物、検証条件を決める。小さな仕事は工程と記録をまとめ、担当や依存関係を分ける必要がある仕事はタスクを分割する。

全体フローから、その段階で必要な工程資料と専門スキルを読む。参照先はこのスキルの実際の配置場所を基準に解決し、作業対象は利用先プロジェクトに保つ。

既存のタスク記録やcheckpointが渡された場合は、記録と実状態を照合して必要な工程から続ける。ユーザーの依頼範囲と既存の承認を引き継ぎ、工程があることを理由に実装・コミット・公開などの操作を追加しない。
