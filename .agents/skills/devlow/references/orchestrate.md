# 複数unitの管理へ接続する

大規模な分担作業、または中規模でも依存・担当交代・再開を台帳で追う必要がある場合に[orch](../../orch/SKILL.md)へ渡す。既存の8工程を各unitに適用し、管理のための別の実装・検証工程は作らない。

計画工程から、親の目的・共通設計・範囲・終了条件、子へ分ける成果物と所有範囲、依存、担当、検証方法と必要な証拠、納品条件、既存のタスクIDと文書を渡す。分割基準と計画の作り方は[plan](plan.md)が所有する。

orchは親・子の更新責任、台帳の操作、提出・受け入れ、判断待ち、担当交代を扱う。CLIの入力や復旧の手順はorch側を参照し、この資料へ複製しない。小規模な子にtask.mdを増やさず、中規模以上の文書は各担当が用意する。

子の結果と証拠は親へ返す。親は子の報告を受け入れた後、統合後の[verify](verify.md)と必要な[review](review.md)を行い、[deliver](deliver.md)へ渡す。レビュー・検証のみの依頼は、その結果報告を受け入れて引き渡し、不合格を理由に依頼外の修正へ進めない。

orchを利用できない場合は各タスクの記録を正本とし、親のplan.mdに子への参照・依存・確認時点の集約を置く。管理できる範囲で順次進め、存在しない台帳やコマンドを利用済みとして扱わない。
