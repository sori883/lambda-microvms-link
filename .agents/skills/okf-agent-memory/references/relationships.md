# 関連付け

独立したconcept間で、根拠・制約・手順・依存・後継などの意味がある関係だけを作る。決定とその理由を別文書へ分割したり、網羅性のために全conceptを相互リンクしたりしない。

## 手順

1. `show` でリンク元とリンク先を確認し、既存の関係と重複しないことを確かめる。
2. `relate` に両方のIDと関係の説明を渡す。説明には、リンク先がリンク元にどう関わるかを書く。
3. 更新後のリンク元を `show` で確認し、`validate --strict --drift` でリンク切れ・孤立・説明の不一致がないことを確認する。

CLIは通常の相対Markdownリンクとして関係を保存する。例えば `rules/auth-tests` から `procedures/auth-test-run` へ「このルールを確認するテスト手順」と説明する。リンク先の本文をコピーしない。

目次は発見の入口、関連リンクは意味のある関係として使う。孤立を解消するためだけに無関係なconceptへリンクしない。IDや配置を変更する場合は、リンク元と目次に残る参照も確認する。

`relate` は同じbundle内のIDを指定する。別bundleの文書は同一bundle内のIDとして渡さず、本文や `sources` に参照先と出所を明示して `update` で保存する。

文書そのものを削除する場合は `delete` が対象文書への関連リンクと目次を整理する。文書を残して特定の関係だけを解除する場合は、リンク元の本文を `update --body-file` で更新する。削除による孤立文書の扱いは [更新・削除](update.md) を参照する。
