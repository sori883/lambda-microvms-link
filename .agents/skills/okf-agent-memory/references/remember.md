# 保存判断

## 次の作業に役立つか

会話を知らない人やエージェントが、同じ調査や誤りを繰り返さずに済む情報を残す。

| 残す情報 | 通常は残さない情報 |
| --- | --- |
| 採用した判断、理由、比較した代替案 | 一時的な案や細部の検討過程 |
| 継続的な要件、制約、ユーザーの方針 | その返答だけに対する表現の指定 |
| 非自明な構造、挙動、再現条件のある発見 | 一般的な構文説明、使い捨てのログ |
| 再利用する手順、不具合の原因と対処 | 会話全文、思考過程、進捗の逐語記録 |

価値がある推測は、根拠・不確実性・確認方法を明示して残す。作業を終えたことだけを理由に文書を作らない。

## 配置と粒度

保存する前に [frontmatterの定義](frontmatter.md) でtypeと保存先を選び、同じ話題を検索する。既存conceptで扱える内容なら更新する。

1つの決定の理由・代替案・影響は同じ文書にまとめる。独立して更新・参照される内容だけを分ける。新規IDには、例えば `decisions/runtime-selection` のように内容を表す名前を使う。新規文書は日本語を基本とし、既存文書の言語は翻訳依頼がなければ保つ。

## 保存

`create` または `update` に、タイトル、自然言語1文の説明、本文、実際の作成主体と必要なメタデータを渡す。参照可能な根拠は `sources` に記録し、確認できない著者・日時・参照先を作らない。参照先のないユーザーの決定は、本文に決定内容と分かっている日付を記す。

`create` / `update` による保存で `generated`、親の `index.md`、bundleの `log.md` を更新する。通常の記録では `--no-index` や `--no-log` を使わない。自動更新した項目を手で重複追加しない。

保存後は `show` で内容を確認し、必要な関連付けを行ってから `validate --strict --drift` を実行する。エラー・警告を解消してから完了とする。内容の確認やユーザーの判断が必要で解消できないものは、未完了事項として根拠とともに報告する。
