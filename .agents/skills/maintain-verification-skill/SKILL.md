# 検証手順を現状と照合する

対象は既存の検証スキル、機能一覧、同スキルが所有する操作スクリプトである。複数候補があり依頼から選べない場合は対象を確認する。

対象が見つからなければ、確認した範囲と「対象なし」を報告する。新規作成が既存の依頼・承認の範囲に含まれる場合だけ [create-verification-skill](../create-verification-skill/SKILL.md)へ渡す。点検・保守だけの依頼を新規作成へ広げず、作成を提案する場合も依頼範囲へ追加されるまでは実行しない。

## 照合する

1. 対象の版、検証スキルの場所、依頼された機能を固定する。一覧と機能ファイルの欠落・重複・切れた参照を調べる。
2. 機能ごとにソースの入口、現在の動作、手順との相違候補、実操作で確かめる方法を集める。最近の変更から一覧にない機能も調べ、追加する場合は実在する入口を示す。
3. 独立したソース調査は利用可能な担当へ分けられる。調査担当は根拠と操作案を返し、共有環境の操作・編集は行わない。実操作の担当が重複する準備をまとめる。
4. 検証スキル自身の起動・状態確認・操作手順を使い、対象機能をそれぞれ少なくとも一度確認する。UI・サーバーの共有インスタンスには操作担当を一人置く。短命のCLIは操作ごとに分離する。

ソースに相違がなくても実操作を省略して検証済みにしない。到達不能な機能は、試した入口と不足する認証・環境等を記録する。実操作が許可範囲に入らなければ、実行せず未確認を残す。

## 相違を分類して直す

| 相違 | 扱い |
| --- | --- |
| 承認された仕様・実装変更を手順が反映していない | 根拠に合わせて手順・機能一覧を更新する |
| 期待する振る舞いは動くが操作スクリプトが壊れている | スキルが所有するスクリプトを修正し、同じ操作を再実行する |
| 製品が契約どおり動かない、変更理由が不明 | 製品の問題または判断待ちとして報告する。実際の不具合に合わせて期待結果を緩めない |

製品コードはこの作業で修正しない。担当範囲外のスクリプトが原因なら、その所有者へ根拠を渡す。

予想外の結果の後は状態確認をやり直す。プロセスが正常でも画面・データ状態が壊れていれば既知の状態へ戻す。自分が開始した試行の残存プロセス・データを片付け、取得済みの証拠は保持する。修正した手順を再実行し、最後の操作後にも後片付けと証拠の残存を確認する。

## 結果を返す

変更不要、更新済み、未完了、対象なしのいずれかを、確認した機能・版・証拠、未確認の入口・前提、製品側の問題とともに報告する。部分的な更新と未確認は併記できる。コミット・PR・定期実行は依頼に含まれる場合だけ行う。
