# 判断ログの形式

新規ログはUTF-8のTSVで、一行目をヘッダーにする。各セルは一行に収め、タブ・改行を空白へ置き換える。表計算ソフトで開く場合の式実行を避けるため、`=`・`+`・`-`・`@`で始まるセルには先頭へシングルクォートを付ける。

| 列 | 内容 |
| --- | --- |
| id | ログ内で重複しない安定したID。追記前に既存IDを照合する |
| ts | この行を記録した実際の日時。タイムゾーン付きISO 8601 |
| run | 実際の会話または実行主体を識別するID。取得できない値は推測しない |
| phase | 工程または作業のまとまり |
| decision | 選択・実施・訂正した内容 |
| why | 判断や訂正の理由。後から記録した出来事なら分かる範囲の発生時点も記す |
| evidence | 主張を確認できるコミット・PR・ファイル・保存した結果の参照。複数ならセミコロンで区切る |
| result | 観測結果、失敗、未確認など。予定を実績にしない |
| supersedes | 誤記を訂正する場合の対象行ID。通常の追記では空欄 |

IDは行番号と分ける。ファイルを読む担当は原履歴を残したまま訂正関係をたどり、元の主張と現在採用する主張を区別する。ログ形式の整合だけでは内容の真実性は判定できない。

既存の別形式を更新する場合はヘッダーを勝手に変更せず、同じ役割の項目で記録する。安定したIDがない既存行を訂正するときは、元ファイルと記録時点・行・内容を特定した参照を作り、新規ID付きの訂正記録から結び付ける。対応を確かめられなければ訂正済みにしない。
